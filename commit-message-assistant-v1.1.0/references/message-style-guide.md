# 提交信息措辞指南（commit-message-assistant）

## 每文件输出结构
对每个改动文件，输出三行：
1. **文件名**（`### 相对路径`）：清晰标注本条 message 对应的文件
2. **message**（粘贴用，单行）：`type(scope): subject`
3. *理由*（不粘贴，斜体）：功能级一句话，说明"实现 / 增添 / 修复了什么"。

示例：
```
### src/auth/login.py
feat(auth): 增加邮箱登录
*理由：新增邮箱格式校验与查重逻辑，供 /login/email 接口使用。*
```

## 相似组聚合输出结构
脚本输出 `SIMILAR_GROUP` 标记的一组同构批量文件（如年份切割出的 `data/2015.json`…`data/2024.json`），整组聚合为一条，仍是三行：
1. **标题行**：`### 目录/（N 个文件：清单）`；清单全列，长清单可用首尾+省略号（如 `2015.json … 2024.json`）。
2. **message**：主题写"批量操作 + 范围/数量"，不逐个列文件名。
3. *理由*：说明同构批量的来源与用途，并提示适合合并为一次提交。

示例：
```
### data/（10 个文件：2015.json、2016.json … 2024.json）
feat(data): 按年份切分数据为 2015–2024 共 10 份 JSON
*理由：切割脚本产物，10 份结构与字段一致（代表文件见采集输出）；适合合并为一次提交。*
```
- 判断依据以脚本为准：只有带 `SIMILAR_GROUP` 标记的组才聚合，其余仍逐文件；无标记而自行"觉得像"不聚合。
- 组内有"行数离群，已详列"的成员 → 理由中点出差异（如"其中 2019.json 多 200 行补充字段"），必要时该文件可单列一条。

## message（单行）写法
- 主语省略，动词性短语起：`feat(auth): 增加邮箱登录`，不要"我增加了邮箱登录"。
- 短：subject 建议 ≤ 20 个汉字；超长拆短句。
- 单文件多变更：type 取主导，subject 短句把次要改动也带上。
  - 例：`feat(auth): 增加邮箱登录，顺手重构校验逻辑`
- 删除文件：`chore: 移除废弃的 legacy_config.js` 或 `refactor: 删除未使用的 utils`。
- 改名：`refactor: 重命名 auth/login → auth/signin`。
- 相似组聚合：subject 含数量/范围。例：`feat(data): 按年份切分数据为 2015–2024 共 10 份 JSON`；批量删除：`chore(data): 清理 2015–2019 共 5 份过期 JSON`。

## 理由（功能级）写法
- 描述"这次改动在功能层面实现了什么"，让用户一眼看出意图，便于判断 / 微改。
- 不逐行列 diff，综合 diff 概括。
- 例（修改文件，+12 -3）：
  - *理由：把登录失败的错误信息细化成"账号不存在 / 密码错 / 已锁定"三种，前端可据此提示；主要改了 LoginService.errorMsg 与 3 个调用点。*
- 例（新增文件，42 行）：
  - *理由：新增邮箱登录后端校验，含格式校验与查重，供 /login/email 接口使用。*
- 例（删除）：
  - *理由：legacy_config.js 的配置已迁到 config/default.js，此文件无人引用，删除以减少歧义。*
- 例（改名）：
  - *理由：统一命名，login → signin，与前端路由对齐；引用处已同步。*

## 输出排列
- 按类型分组：新增 → 修改 → 删除 → 改名。
- 组内按路径字母序；相似组聚合条目占据其代表文件在字母序中的位置。
- 每组前加小标题（二级标题），如 `## 修改`；文件行用 `### 相对路径`，避免同级冲突。
- 改动 > 50 时顶部加一行提醒。

## 好坏对照
❌ `update: 改了点东西`（type 非 Conventional，subject 空泛）
✅ `fix(parser): 修复空字符串导致索引越界`

❌ `feat: 增加邮箱登录邮箱登录邮箱登录功能以及重构了校验逻辑还有修改了样式`（过长、堆砌）
✅ `feat(auth): 增加邮箱登录，含校验重构`

❌ 10 条 `feat(data): 添加 2015.json` … `feat(data): 添加 2024.json`（同构批量逐份凑数）
✅ 一条 `feat(data): 按年份切分数据为 2015–2024 共 10 份 JSON`

❌ 理由：改了 login.js
✅ 理由：细化登录失败错误码，前端据此提示，改 LoginService 与调用点。
